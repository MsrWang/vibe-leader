# 3.0.3：大文件、多文件和长日志先做本地证据筛选

3.0.3 为调查材料较大的任务增加一个可选入口：在阅读大文件、多个文件或长日志时，可以先用本地证据筛选器缩小相关片段，再回到原始文件核对。小范围调查无需使用它。

## 用户会看到什么变化

筛选器不会因安装 Skill 而自动运行。主管判断材料规模确实需要筛选时，才会显式调用随包脚本，并用简短状态说明模式、候选数、选中数、回读数和回退原因。

筛选结果只帮助定位可能相关的证据。没有选中片段不代表事实不存在；关键事实仍缺失时只允许一次有依据的补充筛选，之后应报告证据不足。主管继续负责项目绑定、授权、事实核验、执行决定和验收判断。

## 本版本修改了什么

| 范围 | 变化 |
| --- | --- |
| Skill 包 | 可安装目录从 11 个文件增加到 13 个文件，新增证据筛选说明和标准库脚本。 |
| 本地筛选 | 把相对路径文件切成有界窗口，用确定性词项相关性排序，最多返回 24 个片段。 |
| 精确回读 | 成功前重新打开所有来源，核对文件身份和完整摘要，再按字节区间读取被选片段。 |
| 隐私门 | 查询、路径和完整文本先经过敏感模式检查；命中后阻止选择和回读。 |
| 安装与恢复 | 安装器的精确文件清单、升级候选和恢复合同同步为 13 个文件。 |

## 数据与权限边界

随包实现只提供本地确定性选择器，不调用 Jev API，不读取凭据，不接入后台服务，也不把业务数据发送给外部选择器。它不选择模型或 Agent，不改变当前项目，不授予写入或发布权限，也不判断任务完成。

筛选器不是通用业务数据分类器。未命中敏感模式不能视为允许外发；TikTok、OMS 和其他业务数据仍不得据此发送给第三方。真实路径保留在本机映射中，不进入筛选输出。

当前安全文件读取只支持具备目录相对、禁止跟随链接能力的 Linux/WSL 环境。来源在筛选和回读之间发生变化、平台缺少安全读取能力或输入不能可靠判断时，返回未知状态且不提供片段。

## 已验证与尚未验证

本地筛选行为、Skill 合同、安装器精确清单和恢复路径分别通过聚焦检查，并纳入默认仓库回归。独立审查发现的高优先级问题已在候选中修正；检查使用合成输入和临时目录，没有调用 Jev、读取真实凭据或处理业务项目。

冻结的 13 个文件候选在 Windows Codex Desktop 配合 Ubuntu/WSL 的限定环境完成实际安装：活动文件与候选逐字节一致，清单核验和升级日志均为已验证，旧版本完整归档。安装后又在新任务中确认宿主重新加载了新版。

这些证据覆盖候选字节、限定环境安装和一次重新加载观察。代表性大文件或长日志中的长期自然任务仍需观察；其他宿主、Windows 原生安全读取、外部 Jev 比较、所有语言与所有业务敏感数据识别均未由本版本证明。

## 安装、升级与回退

首次安装按[安装指南](getting-started.md)核对来源、真实 `CODEX_HOME` 和宿主发现。已有 3.0.2 或更早安装需要使用受控升级流程；不要直接覆盖活动 Skill 目录。安装成功、宿主重新加载、筛选结果正确和长期任务表现是不同结论。

需要返回旧版本时，先核对当前安装、成功收据和旧版本归档，再为 `restore-version` 取得新的具体批准。旧升级批准不会自动授权恢复。

轻量纠偏的行为和限制继续见[3.0.2 说明](release-3.0.2.md)。完整数据流、兼容性和公开边界见[限制说明](limitations.md)。
