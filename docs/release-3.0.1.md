# 3.0.1：连续推进到有意义检查点

3.0.1 处理一个直接使用问题：项目、目标、授权和停止条件没有变化时，主管仍可能在普通步骤后结束当前回合，让用户反复发送“继续”。本版本把连续推进条件写入 Skill 主循环，并更新日常用法、维护判断和变化影响说明。

## 用户会看到什么变化

在稳定条件下，主管应连续完成同一检查点内相互依赖的调查、修改、关联核对和必要验证；中间可以简短汇报进度。到达有意义检查点、需要用户决定或批准、出现失败或 `UNKNOWN`，或者触发停止条件时，再结束当前回合。

如果刚完成 Skill 更新，当前任务仍可继续。以后自然开启的新任务用于补充“新版已经加载并产生预期行为”的独立证据，不要求为了测试暂停正在进行的项目。

## 本版本修改了什么

相对 3.0.0，公开源码候选修改七个既有文件并新增本说明：

| 范围 | 变化 |
|---|---|
| Skill | 11 个运行文件中只修改 `SKILL.md`，增加一段连续推进条件；其他十个文件逐字节不变。 |
| 使用说明 | 更新项目接续、Skill 维护和变化影响说明，区分当前推进、候选验证、实际安装和未来行为观察。 |
| 合同检查 | 增加三个静态检查，固定连续推进、维护证据边界及复杂变化补验的必要表述。 |
| 版本入口 | 更新首页、安装指南和变更记录，说明 3.0.1 需要更新实际安装才能获得新规则。 |

程序、安装器、工作台组件、数据格式、其余测试和 HF 静态示例均未修改。

## 已验证与尚未验证

本项目先取得旧文字缺少必要表述的失败，再验证最小修订；Skill 合同、完整仓库回归和静态安全检查通过。冻结的 11 文件候选在 Windows Codex Desktop 配合 Ubuntu/WSL 的限定环境完成一次受控升级：活动文件与候选一致，升级 journal 为 `VERIFIED`，旧版本完整归档。

这些证据证明源码、合同、安装字节和恢复材料；不能证明当前对话已经重新加载新版，也不能推导所有未来任务都会遵守。新任务加载、长期行为、第三方 Skill、新环境、数据迁移和真实业务系统变化仍需对应场景验证。

## 安装与回退

首次安装按[安装指南](getting-started.md)核对来源、目标目录和宿主发现。已有安装需要使用同一指南中的受控升级流程；不要直接覆盖 Skill 目录。升级成功、宿主重新加载和实际行为是三个不同结果。

需要返回旧版本时，先核对当前安装、成功收据和归档状态，再使用新的具体恢复批准执行 `restore-version`。旧升级批准不能自动授权恢复。

3.0.0 的四类使用入口和原限制继续见[3.0.0 说明](release-3.0.md)。
