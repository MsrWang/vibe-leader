# 3.0.0：项目接续与维护用法

3.0.0 在 2.3.1 的基础上增加一组使用说明，帮助你在阶段成果完成后接回整体目标，并把质量检查、Skill 维护和需求变化的影响放进同一条项目主线。这个版本的增量是**说明与导航**：程序、Skill、安装器、测试和在线示例都沿用 2.3.1。

## 从哪里开始

在当前项目显式选择“中文跨项目研发主管”，按[日常项目用法](project-workflow.md)选择最贴近当前问题的请求。主管应先核对项目、有效目标和已有结果，再说明这次最重要的缺口、需要采取的行动，以及行动后怎样看效果。

| 当前遇到的问题 | 对应入口 | 你应看到的结果 |
|---|---|---|
| 一项工作做完，不清楚整体还差什么 | [继续整体项目](project-workflow.md#阶段做完后继续整体项目) | 已完成部分、剩余目标、下一项有依据的行动 |
| 怀疑代码质量有问题 | [检查代码质量](project-workflow.md#检查代码质量找值得处理的问题) | 具体问题、优先级、修复范围与相关验证 |
| 想调整本项目负责的 Skill | [维护 Skill](project-workflow.md#维护当前项目负责的-skill) | 先辨别规则、执行、调用或环境问题，再决定是否修改 |
| 需求发生变化 | [核对连带影响](project-workflow.md#需求变了核对连带影响) | 受影响的代码、步骤、说明和需要补验的证据 |

质量、规则维护和影响判断的具体方法见[维护说明](maintenance-and-change.md)。这些入口不会自行启动任务或取得写入权限；实际行动仍取决于当前项目事实和本次授权。

## 已有依据与尚未覆盖的部分

2.3.1 的工具修复、报告阅读和既有 Skill 边界有各自的验证记录；它们按未变内容继续适用。本项目另有一次阶段完成后接续整体目标的实际应用、一次程序异常修复，以及一次检查后保留 Skill 规则的维护应用。这些结果支持对应场景的用法，不构成四类入口在所有项目都稳定有效的证明。

目前没有新规则修订后的行为观察，也没有复杂数据变化、环境迁移、第三方 Skill 维护或长期跨任务可靠性的验证。遇到这些情形，应先明确实际输入和受影响路径，再做相应检查；未知结果应保留为未知。旧版工具、安装和环境的限制继续见[已知限制](limitations.md)。

## 安装与回退

3.0.0 的 11 个 Skill 安装文件与 2.3.1 相同。已有正确安装的用户可直接阅读新增说明，无需为此重装；首次使用仍按[安装指南](getting-started.md)核对宿主与来源后安装。阅读说明不会让源码工具自动运行，也不会更新正在使用的 Skill。

如果新增用法不适合当前任务，可以继续按 2.3.1 的原使用方式工作。需要切换实际安装版本时，先核对当前安装来源、状态和恢复路径；不要用源码目录或旧文件直接覆盖现用安装。公开版本和完整源码以[版本下载页](https://github.com/MsrWang/vibe-leader/releases)为准。
