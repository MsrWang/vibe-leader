# 限制、数据流与验证边界

2.3 已完成独立源码交付和限定环境的用户验收。3.1 当前是 macOS 本地候选准备，真实 Mac 验收尚未完成；候选边界见[3.1 说明](release-3.1.0.md)。本文保留产品限制；既有实际证据范围见[2.3 验证说明](release-2.3.md)。

## 指令不是强制沙箱

当前可安装的 Skill 源码目录包含精确 13 个文件，并附带一个可选的本地证据筛选脚本。脚本只在大文件、多文件或长日志调查中被显式调用；它不会仅因 Skill 被安装就自动拦截每次对话或工具调用。其他 Python 治理校验器仍保留在完整源码中，需由用户显式运行或在任务中明确使用。

项目绑定、审批与失败关闭是工作合同，不是内核权限。模型可能偏离指令；实际隔离取决于宿主的权限、沙箱、工具与配置。本项目不承诺所有模型、所有版本都确定遵从。部署准备度为 Go 也不自动授予部署权，技术测试 PASS 不产生用户接受。

## 本地不等于离线

一般数据流是：

`你的请求/获准读取的文件 → Codex 任务上下文 → 配置的模型服务 → 模型回复与获准工具操作`

Skill 文本会参与上下文。所选模型服务、账户方式与保留政策由实际宿主及服务配置决定，本项目不保证“代码不离开电脑”或“服务端零日志”。

可选扩展或 MCP 工具可能将相应输入交给第三方；是否安装、可用、联网和写入必须分别确认。基础 Skill 不要求配置新的模型服务，不收集维护者凭据，不附带后台服务、遥测上传器或自动发布流水线。源码评测入口可以启动真实 Codex/模型，不能因为源码在本地就当作无网络的单元测试。

当前证据筛选脚本只做本地读取和排序，没有 Jev API、凭据读取或网络功能。它的敏感模式检查不是通用业务数据分类器；未命中不构成向外发送的许可，TikTok、OMS 和其他业务数据默认不得发送给外部筛选服务。

项目绑定/清单工具和评测产物可能包含路径、环境或任务证据；公开输出过滤不等于所有原始文件均可分享。分享前应逐文件脱敏；不把配置、日志、安装备份或完整会话提交到公开仓库。

## Git 身份采集

身份工具只运行固定的 Git 查询命令，禁用文件监视钩子、分页器和缺失对象自动拉取，清除继承的 `GIT_*` 覆盖并忽略全局/系统 Git 配置。需要 Git 支持 `--no-lazy-fetch`，判定 unborn 还需要 `show-ref --exists` 区分引用缺失与查询错误；不支持或缺少本地对象时失败关闭。仓库内排除规则仍生效。它依赖可信的本机 Git/Python，不是恶意可执行文件的沙箱。

identity 外层仍为 schema 2，内容指纹升级为 `dirty_fingerprint_schema=3`：记录 HEAD、索引、已跟踪文件原始字节/模式/链接文本和未跟踪文件内容，不调用 `status/diff` 的内容转换路径，不执行 clean/process filter 或 textconv。旧格式不可用作新的有效绑定，须重新采集，不得仅改版本号。原始字节与索引不同即保守标记 dirty；CRLF、过滤器或可执行位配置可能使它与普通 `git status` 的干净状态不同。

已跟踪符号链接只记录链接文本，不读取目标。子模块的 gitlink 不能证明嵌套工作区内容，已存在的子模块目录返回 `tracked_submodule_not_fingerprinted` 和 BLOCKED，不能据父仓库摘要取得写入资格；当前没有完整子模块内容采集。路径替换、特殊文件、指纹不完整继续失败关闭。已跟踪文件按原始内容读取，大仓库采集耗时取决于实际文件大小。

身份采集支持 SHA-1 与 SHA-256 仓库，不代表全部可选工程链都支持：当前隔离写入委派的 candidate Git hash 合同只接受 40 位，SHA-256 候选会被拒绝。首个支持环境的原生主线程流程不依赖这一可选写入接口。

## 安装、升级与恢复

- 安装拒绝覆盖已有目标/状态，不把删除 staging 当成通用修复办法。
- `rollback` 是把当前安装和状态归档的可恢复卸载；升级后回到归档版本使用 `restore-version`，两者不是同义命令。
- 切换后端可能存在非原子的短暂不可用窗口；功能正常或字节相同不能证明所有权限和文件系统属性保真。
- UNKNOWN 结果保留 payload、manifest、journal；不重试或逆操作。旧摘要、旧审批和旧后端证据不能直接续用。
- 私人事故专用 `archive-staging` 入口不公开；通用库内恢复安全性质与合成测试保留，但不是任意目录的一键修复承诺。
- 在已验证环境已完成旧版恢复及返回 2.3；其他环境、后端和归档须另验，不能把这次成功当成任意恢复保证。
- 文件许可通知会改变候选哈希，最终发行包须重新核验；不能拿通知前的候选或旧安装成功记录给新字节背书。

## 评测入口是高级功能

普通使用不需要运行 `workbench.evaluation_surface`。仅查看帮助不会启动模型：

```bash
python3 -B -m workbench.evaluation_surface --help
```

真实评测须另行绑定本次模型调用、路径、预算与批准。当前路径合同要求明确的受保护项目根、候选与评测根；缺少身份关系、权限/挂载不一致、路径别名或存在性见证不明时失败关闭。probe v2 拒绝旧标签/旧批准，不自动迁移。

生产准备使用固定系统 PATH（`/usr/local/bin:/usr/bin:/bin`），必要工具必须在该路径可发现；不会借用任意用户 PATH 回退。合成测试中注入的 fake 工具不能证明实际宿主已具备运行条件。

合成场景的模型输入只包含提取/渲染后的用户输入，不附评分答案；三场景文件是测试材料而非真实结果。合成 fake 进程、源码权限断言、实际 OS 遮蔽效果、真实模型响应与人工评分分别计证据，不能相互替代。

## 运行证据接入的边界

[入门指南的高级源码流程](getting-started.md#6-高级源码用法接入运行证据)复用现有采集器，不另建宿主发现或证据存储系统。项目 OS/WSL 事实与程序版本/SHA-256 分开计证据，缺失不得降级；版本或程序变化继续令旧结果 STALE。

- `inspect --capture-runtime` 实际启动三个程序命令并创建临时环境/输出，虽不请求模型 turn，也不是纯只读或硬网络沙箱。必须先明确真实程序、路径、可接受副作用及本次执行批准；仅有代码修改批准不够。
- 采集器仍要求固定 feature 合同、20 项 schema 检查和空 stderr；新宿主可能不兼容。非零、超时、不支持或证据缺失保留 UNVERIFIED，不放宽合同、不改哈希、不用 fake 成功替代宿主成功。
- `import-runtime` 是已有记录的窄导入器，不执行记录里的 argv；只校验所用程序证据及记录的一致性，不重新认证全部 feature/schema 内容。原采集目录必须保留。伪造或重放记录、把别的主机 identity 与程序拼在一起，不会因此成为真实采证；调用方须维护来源及派发/接收时序。
- `core_sha256` 只覆盖显式路径所指的单个普通文件，不覆盖所有解释器、包装器目标、动态库、配置、模型服务或远端 Agent。不能拿脚本启动器的哈希声称整个宿主运行时未变；真实使用哪个程序仍须另核对。
- 版本字符串只接受与原始输出摘要一致的单行 UTF-8（无行尾/LF/CRLF）；不支持的格式停止调查。identity schema 2、runtime 精确三字段和 freshness 输出 schema 2 不能靠重命名旧 inventory/environment 字段伪造迁移；delegation evaluation 的新生命周期输出为 schema 3。
- 上下文准备成功不是运行新鲜，也不是接收或授权。漂移会原样进入 evaluator 并被拒绝；缺失/畸形证据无有效消费记录。当前程序证据由主线程提供，不是远端 Agent 的程序证明。
- [新 v2 接收接口](getting-started.md#64-新委派的接收生命周期本地候选接口)要求主线程提供完整生命周期及材料核验声明，只读重验策略必须在新派发前固定。v1 仅诊断，不能靠追加字段/摘要复活旧结果。暂停、取消、撤销、任务切换或明确打断均不得通过普通恢复消除。
- 接收器不是事件采集器或认证系统，不能识别被隐瞒的事件、伪造的 true 或被调用方改写的全部输入。主线程必须核验原生任务、实际批准和完整工具轨迹；证据不足失败关闭。事件列表、摘要、消费记录均不授予调用或写入权限，也不替代独立审查与人工验收。已有模型观察和独立审查只覆盖[验证说明](release-2.3.md)列明的范围，不认证调用方提交的全部事实。

接入的合成验证使用本地 Git 身份、注入进程输出和既有 fake CLI；这些证据不证明真实宿主兼容。维护者本机的受限采集也不能替代目标用户环境的验证；Windows-native、模型、安装、候选独立性与用户主循环仍需各自的适用证据，不能由本地测试外推为通过。

## 测试与证据边界

机械性接口一致性、模型真实行为和用户使用验收是三类证据。文档字段由真实接收器配合合成身份校验，只能证明字段组合与现有接口相容；不能证明模型读懂、完整交付或遵守安全规则。公开文档更新不改接收器或已安装副本，已有四类对照样本也不代表任意模型的完整行为通过。

固定参数材料入口只在本地临时证据目录验证，不进入当前 13 文件 Skill 或安装器。期望摘要须在阶段入口预先固定，不能从待验证文件现算后自证；模型只选择受限短标识。入口本身、解释器和源文件仍需主线程在阶段边界核对。它不调用模型、不管理权限/预算，不保证原生模型以后必然正确使用入口，也不是 OS 沙箱。真实派发和独立审查须另行绑定材料、范围、预算与授权。

可先运行 README 的小范围确定性自检。运行完整 `unittest discover -s tests` 前，确认它会创建和清理自有临时文件、合成 Git 仓库及安装 fixture；部分 Skill 清单测试在源码父目录建立自己的临时根。WSL 的两个项目身份测试还会查询 Windows 临时路径，并在自有目录模拟根替换。另有独立 opt-in 的 Windows 安装集成。不要未经确认就执行全量或启用这些开关。

测试不应指向真实 `CODEX_HOME`、业务项目或现有安装。调整测试环境不能通过删除用例、增加 skip 或放宽负例来掩盖问题；skip/NOT_APPLICABLE、UNKNOWN/UNVERIFIED 和失败要分别报告。
