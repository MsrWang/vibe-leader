# 自用减负：只读自检、精简入口、反馈模板

用户已选择这三个交付项。基线为稳定版 3.0.3 的公开源码；本轮形成可审阅的本地改进。

## 使用结果

- 从首页直接找到首次使用、继续项目和排查入口。
- 在完整源码根运行 `python3 -B scripts/doctor.py`，得到中文状态和一个下一步；`--json` 提供同内容的结构化结果。
- 安装完整性、版本文件内容、宿主发现记录、实际调用各自呈现，缺失证据明确保留。
- GitHub 提供使用问题和体验反馈两种简短模板。

## 自检实现

独立源码脚本复用 `scripts/install_skill.py` 的目录校验、清单核验与文件扫描，以及 `workbench.skill_inventory.assess_skill_route` 的发现结果核对。脚本仅支持 Linux/WSL；其他平台输出未验证状态。本轮不修改安装器、13 文件 Skill 或 Mac 候选。

默认只使用已设置的 `CODEX_HOME/skills`。可用 `--skills-root` 明确路径，但它必须与真实 `CODEX_HOME` 一致。路径未设置时返回待确认，禁止猜测另一套安装根。完整性核验只读指定 Skill 及其安装清单。

清单没有发行版本字段，因此版本栏只报告文件内容是否匹配已知 3.0.3 指纹，以及是否与当前源码一致。它不把匹配当成下载来源认证，也不把不同内容直接判为损坏。

可选 `--discovery FILE --project PATH` 接收已有的 `skills/list` 原始响应，复用既有路由核验并固定目标 locator。结果仅代表输入快照；不执行宿主发现，不运行 Codex 或模型，也不把快照校验当作当前 App 加载成功。实际调用始终列为未检查并给出手动观察步骤。

输出不含原始日志、清单、业务内容或本机路径；只包含固定状态、已知原因、摘要及计数。所有结果输出到 stdout，不自动保存，不发网络请求，不写探针，不创建 Python 字节码。检查不是原子快照或权限保证。

退出码：0 表示本轮本地文件核验完成；2 表示参数、环境或证据不足；3 表示已发现安装漂移或提供的发现记录存在阻断。退出 0 不代表 App 或用户验收通过。

## 文档与反馈

首页先呈现用途和三条入口，历史更新集中到后部。新增自检说明解释命令、状态、退出码和手动观察；日常项目用法增加可直接复制的简短接续入口。已有详细安装与恢复说明继续提供其完整步骤。

使用问题模板包含版本/环境、预期、实际、最小复现。体验反馈包含任务、顺畅或费力之处、希望改善的结果。自检摘要可选，不要求上传完整会话或安装目录；安全问题沿用 SECURITY.md。

## 检查范围

初次实现阶段仅做静态检查。后续范围已扩展为功能测试、相关回归和通过后的 GitHub 源码更新。测试使用临时安装与合成发现记录，不接触真实安装，不将文件或记录核验外推为 App 验收。具体命令与结果记入实施计划及自检说明。
