# 3.0.2：感觉跑偏时，先做最小纠偏再继续

3.0.2 处理一种常见但难以准确描述的情况：项目围绕局部问题不断优化，每一步都可能有理由，但整体方向开始偏离；用户能感受到不对，却不一定能先判断是需求、计划、代码还是 Skill 规则的问题。

## 用户会看到什么变化

在当前项目任务中，你可以直接说“我感觉当前推进有偏差，但说不清技术原因”。主管会把整体目标、最新有效决定、当前行动和直接证据重新对齐。

默认只显示三行：

```text
纠偏判断：当前是否偏离，以及属于哪一类。
最小修正：停止、保留和恢复什么。
现在继续：现有授权内立即执行的下一项。
```

仍服务整体目标的成果会保留，只重新打开受影响的步骤。修正仍在已有授权内时，主管说明后继续推进；同一信号没有新证据，且目标、行动和授权没有变化时，不要求用户再次解释。

只有目标冲突、证据不足、需要用户决定，或者用户要求详细解释时，才展开完整判断。纠偏不产生新的授权；新项目、新目标、账号、网络、安装、发布或其他外部动作仍使用原来的决定与权限边界。

## 本版本修改了什么

| 范围 | 变化 |
| --- | --- |
| Skill | 在主循环接入轻量纠偏；在主管工作流中定义六类判断、三行默认输出、成果保留、重复信号处理和权限边界。 |
| 使用说明 | 新增独立纠偏卡，并把入口接入日常用法、安装指南和维护说明。 |
| 静态示例 | 增加一个“感觉项目跑偏”的合成案例；页面仍不调用模型、不读取项目、不接收表单或建立追踪。 |
| 合同检查 | 固定公开版本说明、升级提示、纠偏示例和运行规则之间的一致性。 |

安装器、工作台程序、数据格式和其余九份 Skill 运行文件没有因为本版本改变。

## 已验证与尚未验证

未修改的 3.0.1 先接受六个合成情境的封闭行为基线，其中四个情境至少有一项失败。最小修订后，同一组六个合成情境全部通过，原先失败的六项标准恢复，也没有让原本通过的标准回退。

确定性合同、完整仓库回归、链接、隐私扫描、补丁正反应用和候选重建分别检查。冻结的 11 文件 Skill 候选还在 Windows Codex Desktop 配合 Ubuntu/WSL 的限定环境完成一次实际安装：活动文件与候选逐字节一致，安装核验和 journal 均为 `VERIFIED`，旧版本完整归档。

这些证据证明本次规则、封闭情境、候选字节和实际安装。合成情境不是长期自然项目；实际安装也不证明当前已经打开的任务自动重新加载。不同宿主、第三方 Skill、复杂数据或环境迁移仍须按对应场景核对。

## 安装与回退

首次安装按[安装指南](getting-started.md)核对来源、真实 `CODEX_HOME` 和宿主发现。已有 3.0.1 或更早安装需要使用受控升级流程；不要直接覆盖活动 Skill 目录。安装成功、宿主重新加载和实际行为是三个不同结果。

需要回到旧版本时，先核对当前安装、成功收据和旧版本归档，再为 `restore-version` 取得新的具体批准。旧升级批准不会自动授权恢复。

日常提示词和更详细边界见[独立纠偏卡](deviation-correction.md)。连续推进的原始维护说明见[3.0.1 说明](release-3.0.1.md)。
